# V50 · 직원 업무 영역별 주소 분리

## 목적
기존 직원 사이트는 모든 업무가 `/staff/` 한 화면에 모여 있고, 새로고침하면 첫 화면으로 돌아가며, 공유 가능한 업무별 주소가 없었습니다.

V50에서는 **동일 도메인의 개별 경로**로 5개 업무 영역의 바로가기 주소를 제공합니다. 로그인과 Google Apps Script, 스프레드시트 데이터는 **기존 시스템을 그대로 공유**합니다.

| 영역 | 바로가기 | 기본 메뉴 |
|---|---|---|
| 상담·등록 | `/staff/consult/` | 체험·클래스 상담 |
| 클래스 운영 | `/staff/class/` | 클래스 시간표 |
| 오감놀이 준비 | `/staff/sensory/` | 월간 오감놀이 계획 |
| 이용료·문서 | `/staff/service/` | 수업비·환불 기록 |
| 스튜디오 관리 | `/staff/admin/` | 시설·운영 점검 |

각 경로는 중앙 로그인 페이지 `/staff/?area=...&page=...`로 안전하게 연결됩니다. 개별 경로를 브라우저에 저장하면 해당 업무 화면이 자동으로 열리고, 로그인 후에도 지정한 메뉴로 이동합니다.

기존 메뉴에서 다른 화면으로 이동하면 URL이 해당 업무를 가리키도록 변경되며, 브라우저 뒤로 가기/앞으로 가기도 지원합니다. URL에는 영역과 화면 ID만 포함하고 로그인 토큰·보호자 정보·스프레드시트 ID를 넣지 않습니다.

## DNS·서버 구조
- **현재 구현은 별도 서브도메인이 아닙니다.** `consult.bridgewonder.bridgeacademy.co.kr` 등 실제 서브도메인을 만들려면 도메인 소유자의 DNS/CNAME 및 GitHub Pages/호스팅 설정이 필요합니다. 코드만으로 DNS를 변경할 수 없습니다.
- 지금은 기존 도메인 안에서 경로를 분리해 사용하므로 추가 DNS나 새 인증 서버가 필요하지 않습니다.
- `/staff/consult/` 등의 정적 진입 경로는 기존 `/staff/`로 이동합니다. **독립된 서버나 독립 배포 앱이 아니며** 현재 로그인·데이터 접근 권한은 동일합니다.
- 역할별 권한은 기존 `BW24_CAPS`와 Apps Script 권한 검사에서 그대로 적용합니다. URL을 직접 입력해도 허용되지 않은 업무는 열리지 않습니다.

## Google Sheets
- 직원 업무 데이터는 원래부터 기존 Google Apps Script/Sheets를 통해 읽고 씁니다.
- V50은 **기존 스프레드시트의 시트·데이터·권한·함수를 수정하지 않습니다.** 새로 설치하거나 재배포할 Apps Script 코드가 없습니다.
- 업무 화면에 입력한 값은 기존 저장 버튼과 서버 로직을 그대로 사용합니다. **자동저장이나 GAS 재배포의 자동화는 구현하지 않았습니다.**
- 서버 측에 추가해야 하는 기능(예: V49 재무 기록, V45 수업안 업로드)은 각 기능의 Apps Script 설치가 여전히 필요합니다.
- GitHub에 코드를 올리는 것만으로 스프레드시트 작업값이 자동으로 반영되거나 새로운 GAS 함수가 생성되지는 않습니다.

## 앞으로의 운영 구조 제안
1. 먼저 업무별 바로가기 URL을 사용해 화면 접근과 직원 업무 동선을 단순화합니다.
2. 기존 수납·급여·수업안·문서 서버가 모두 최신 버전인지 확인합니다.
3. 이후 자동저장/시트 변경 반영/업무별 독립 배포가 필요하면 각 기능의 서버 계약·권한·백업부터 분리하여 별도 버전으로 구축합니다. 실시간 양방향 동기화와 자동 배포는 별도의 기술 과제입니다.
