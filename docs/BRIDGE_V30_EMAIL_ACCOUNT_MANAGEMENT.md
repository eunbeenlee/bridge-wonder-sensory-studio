# Bridge Wonder V30 — 이메일 로그인·직원 비밀번호 발급·직접 변경

## 변경 범위
- 직원 계정 ID는 기존과 동일하게 `관리자_계정` 시트의 `이메일` 열을 사용합니다.
- 원장이 기존 **선생님 계정·권한** 메뉴에서 이름·이메일·역할·담당 반·연락처 열람 여부를 등록합니다.
- 등록 후 계정 목록의 **임시 비밀번호 발급**을 클릭하면 브라우저 보안 난수로 만든 20자리 임시 비밀번호가 **한 번만 표시**됩니다. 원장이 별도 안전한 경로로 직원에게 전달합니다.
- 신규 직원과 재발급 직원은 임시 비밀번호 로그인 후 다른 메뉴에 접근하기 전에 **본인 비밀번호 변경**을 완료해야 합니다.
- 모든 직원은 로그인 후 **비밀번호 변경** 버튼으로 현재 비밀번호를 확인하고 본인이 새 비밀번호를 설정할 수 있습니다.
- 비밀번호가 변경/재발급되면 기존 로그인 세션이 모두 무효화됩니다. 비밀번호 재설정 이메일 OTP도 기존 방식대로 이용할 수 있습니다.

## 보안
- 원문 비밀번호와 브라우저 비밀번호 검증값(proof)은 시트, GitHub, URL, 저장소, 실행 로그에 기록하지 않습니다.
- 비밀번호 검증값은 기존 V29 WebCrypto PBKDF2-SHA256(160,000회) + 서버 pepper HMAC 방식으로 Script Properties에 저장합니다.
- 계정 목록·담당 반·역할·상태는 비공개 Google Sheets에 있습니다.
- 계정별 로그인 세션 revision 및 첫 로그인 변경 플래그는 `BW30_AUTH_<해시>` Script Properties에 있습니다.
- 발급·변경 API는 서버에서 각각 원장 권한과 본인 비밀번호를 검사합니다. UI 숨김만으로 권한을 처리하지 않습니다.
- 스크립트 접근권한은 반드시 기존 직원 전용 프로젝트를 사용합니다. 일반 학부모 공개등록 스크립트에 섞지 마세요.
- 세션 캐시는 기존 60분 만료를 유지합니다. 비밀번호 변경 시 즉시 revision을 증가시켜 이전 세션을 차단합니다.
- 임시 비밀번호가 화면에 표시된 동안 주변 사람이 보지 않도록 주의하고, 클립보드 사용 후 내용을 지우세요.

## 설치 순서 — 중요
**새로운 Apps Script 프로젝트를 만들지 않습니다.**

1. 현재 직원용 Apps Script 프로젝트의 `Code.gs`, `StaffBridge.gs`, `Admin.html`과 연결된 스프레드시트를 백업합니다.
2. 이 PR의 `server/apps-script/Code.gs`를 기존 직원 프로젝트의 **Code.gs 전체에 덮어씁니다.**
3. `server/apps-script/StaffBridge.gs`를 기존 **StaffBridge.gs 전체에 덮어씁니다.** 새 직원 비밀번호 발급·변경 API를 HTTP 허용 목록에 추가했습니다.
4. `server/apps-script/Admin.html`을 기존 **Admin.html 전체에 덮어씁니다.**
5. 기존 `Payroll.gs`, **Script Properties** (`SPREADSHEET_ID`, `OWNER_EMAIL`, `BW23_PRIVATE_PEPPER` 등)은 그대로 유지합니다.
6. **초기 설정/시트 생성 함수는 재실행하지 않습니다.** 배포 관리에서 직원 웹앱의 **기존 배포**를 편집하여 **새 버전으로 배포**합니다. 기존 `/exec` 주소를 바꾸지 않습니다.
7. Google 서버 V30 배포가 먼저 완료되었을 때에만 GitHub **이 PR을 `main`에 병합**합니다. `main`에는 자동으로 `/staff/` 관리 화면 V30이 반영됩니다.
8. 브라우저 강력 새로고침 후 원장 계정 로그인 → 테스트용 직원 계정 등록 → 임시 비밀번호 발급 → 직원 첫 로그인 → 비밀번호 변경 강제 화면 → 새 비밀번호 재로그인 → 원장 권한 확인 순으로 검증합니다.
9. 실제 급여, 수납, 수강생 기록은 변경하지 말고 조회만 테스트하세요.

## 속도
V29의 브라우저 PBKDF2/WebCrypto, 짧은 계정 조회 캐시, 로그인 지표 측정을 유지합니다.
새 계정 등록·비밀번호 발급·변경 기능은 로그인 평시 호출에 추가적인 시트 쓰기를 하지 않습니다.
다만 세션 폐기 검사를 위한 Script Properties 조회가 있으므로 **8초 로그인에서 1~2초로 단축된다고 보장할 수 없습니다.**
`BW29LastLoginTiming`과 `BW27Bridge.metrics()`로 브라우저·Google 처리시간을 확인해 주세요.

## 회귀 검증
- `npm run check`: 전체 프로젝트 JS/GS 문법, layout 재생성 일치, 파일 참조 확인
- `npm test`: 계정발급·세션폐기·권한 분리 포함 기존 회귀 테스트
- Google 실제 서비스의 첫 사용, Google 배포 권한, 메일 인증 흐름은 브라우저에서 직접 점검해야 합니다.
