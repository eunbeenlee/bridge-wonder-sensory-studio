# Bridge Wonder V37 — 간편 상담·등록, 학생기본정보, 월간 체험테마

**적용 상태:** 기능 개발 브랜치. 실제 Google 서버는 업데이트하지 않았으며, `main` 병합 이전에 직원용 Apps Script를 먼저 업그레이드해야 합니다.

## 간편 상담 → 협의 → 정식 등록
1. 홈페이지 어느 페이지에서나 **간편 등록 상담**을 누릅니다. `/sensory-studio/visit/#online-inquiry`로 이동하며 로그인이나 수업반 선택이 필요하지 않습니다.
2. 보호자 성함·연락처, 아이 이름·월령, 문의 종류, 연락 방법을 입력합니다. 주간 수업횟수는 **미정/주 1회/주 2회** 중 선택할 수 있으며 요일·시간을 요구하지 않습니다.
3. 기존 상담 서버에서 접수번호를 발급하며 민감정보 없이 상담 대장에 저장됩니다. 새 보호자 성함과 주간 횟수는 기존 메모 필드의 `[보호자:...][희망횟수:...]` 표기로 함께 보관되어 기존 서버 API를 변경하지 않아도 됩니다. 새 필드가 별도로 지원될 경우도 고려해 전송 값은 명시적으로 검증합니다.
4. 관리자 메뉴 **학생 기본정보 관리 → 최근 상담 접수 → 학생 초안으로 옮기기**에서 기존 접수 내용을 불러와 부족한 정보를 보완한 후 `임시등록`으로 저장합니다.
5. 희망 시기와 시간대를 상담한 뒤, **서로 다른 두 수업반까지** 배정할 수 있습니다. `재원`은 실제 보호자 확인 증빙, 생년월일, 수업반을 확인한 후에만 처리합니다.
6. 정식 수강계약(교습비·기간·서명)은 기존 `/sensory-studio/enroll/`에서 수업 조건을 선택하고 확인·전자서명하는 별도 절차입니다. **임시등록이나 상담 접수만으로 계약이 성립하거나 결제가 완료된 것으로 표시하지 않습니다.**

## 학생 관리 기능
- 별도 비공개 Google Sheets `운영_학생기본정보`에 직접 등록 학생을 보관합니다.
- 기존 보호자 전자서명 대장 `수강등록` 원본은 수정하지 않습니다.
- 이름·생년월일(초기 선택)·보호자·연락처·수강 희망횟수·첫/두번째 수업반·상태·증빙 위치·메모를 관리합니다.
- 상담 접수번호로 이력을 이어붙이고 중복 등록을 감지합니다.
- `임시등록`, `재원`, `휴원`, `퇴원`을 구분합니다. 상담 초안과 휴원/퇴원은 출결에 포함하지 않습니다.
- 확인된 `재원` 학생만 반별 출결, 정원, 보강, 수납 목록에 연동합니다. 2회 수강 학생은 두 수업반 명단과 각 반 정원에 별도로 1명씩 반영됩니다.
- 보호자 개인정보 조회/변경은 `owner`/`director` 계정에 제한합니다. 선생님은 기존 담당 반 학생 명단에서 허용된 연락처만 확인할 수 있습니다.
- 건강·알레르기·질병·주민등록번호 등 민감한 정보는 일반 인적사항 화면에 입력하지 않습니다. 문서 증빙은 비공개 Drive 참조로 남깁니다.

## 매월 홈페이지 체험 테마 운영
- 기존 `운영_월간공통주제`는 **교사용 내부 수업 계획**으로 유지합니다.
- 새 `운영_체험테마공개`는 **학부모에게 공개할 세 가지 체험 테마**를 월별로 편집합니다.
- 달 선택 → 월간 제목·설명 → 세 가지 테마 제목·활동 내용·키워드·이미지 선택 → `초안/공개/보관`.
- `내부 수업 주제 가져오기`로 확정된 공통 주제 제목·활동 문구를 가져올 수 있지만 최종 공개는 관리자 수동 승인만 허용합니다.
- `공개`를 선택한 월만 홈페이지·체험 페이지에 반영됩니다. 정적인 2027년 1월 기본 카드가 남아 있으므로 서버 준비 전에도 페이지는 정상 표시됩니다.
- 공개 목록은 서버가 **체험 제목·활동 설명·정적 이미지 코드**만 제공하며 학생·보호자·서명정보를 절대 전달하지 않습니다.
- **별도 업로드 없이 기존 브랜드 일러스트 5종** 중 선택합니다. 초기 비용은 없습니다.

## 서버 설치 (중요)
기존 직원 전용 Apps Script 프로젝트에 다음 작업을 **한 번에** 수행해야 합니다.

1. 기존 `Code.gs`, `StaffBridge.gs`, `Admin.html`, `Payroll.gs`를 백업합니다.
2. 이 브랜치의 `server/apps-script/AcademicManagement.gs`를 **새 Apps Script 파일**로 추가합니다.
3. 이 브랜치의 `server/apps-script/Code.gs`와 `server/apps-script/StaffBridge.gs`로 기존 같은 이름 파일을 업데이트합니다.
4. `Payroll.gs`, 스프레드시트, Script Properties는 유지하고 초기 데이터 삭제·초기화는 실행하지 않습니다.
5. 직원 웹앱 **기존 배포를 새 버전으로 업데이트**합니다. 기존 `/exec` 주소를 유지해야 공개 테마도 동작합니다.
6. 관리자 계정에서 학생 목록 조회·임시등록·수업반 2개 선택·증빙 검증, 체험 테마 작성·공개 API를 테스트합니다.
7. 그 다음 이 PR을 `main`에 병합하여 GitHub UI를 적용합니다. 사이트의 공개 테마 자동반영은 Google 웹앱의 `?view=experience` 출력이 브라우저에서 접근 가능해야 합니다.

## 보안·호환성
- 프런트엔드 코드는 신규 학생 데이터를 브라우저 영구 저장소나 GitHub에 보관하지 않습니다.
- 기존 상담 API를 재활용하므로 **상담 서버 자체는 변경하지 않습니다.** 신규 인적사항은 기존 상담 대장의 비공개 업무 메모에 들어갑니다.
- 향후 독립적인 동의 원본·정식 계약 확인이 필요합니다. 정보 접수 자체가 보호자 서명으로 대체되지 않습니다.
- 최초 사용자 테스트에서는 가상의 이름·전화번호만 사용하고, 실제 학부모 자료로 테스트하지 마세요.
- 테스트: `npm run check`, `npm test`, GitHub CI의 `tests/academic-management-v37.test.cjs`.

**주의:** `학원법`에 따른 교습계약·영수증과 개인정보 동의 여부는 실제 운영 절차에서 확인해야 합니다. 일반 학생 기본정보 화면에서 자동 충족 처리하지 않습니다.
