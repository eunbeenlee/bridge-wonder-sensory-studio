# V26 급여 서버 운영·검증 안내

검토 기준일: 2026-11-20 (한국 시간)

## 설치 위치와 초기 설정

`server/apps-script/Payroll.gs`를 기존 **직원 운영공간** Apps Script 프로젝트에 추가합니다. 공개 상담·수강 신청 프로젝트에 넣지 않습니다. 기존 `Code.gs`의 `bw17Authorized_`, `bw17Book_`, `bw17Config_`를 사용하므로 같은 프로젝트에 있어야 합니다.

원장 Google 계정으로 Apps Script 편집기에 접속하여 `setupBridgeWonderPayrollV26_`를 한 번 실행합니다. 이 함수는 `Session.getActiveUser().getEmail()`과 `OWNER_EMAIL`을 대조하며, 끝의 밑줄 때문에 브라우저의 `google.script.run`에서 호출할 수 없습니다. `getEffectiveUser()`로 실행 주체를 원장으로 오인하지 않습니다. 재실행해도 기존 자료를 덮어쓰지 않습니다.

초기 설정은 다음 네 시트를 추가합니다. 기존 수강생·직원 계정 시트는 변경하지 않습니다.

| 시트 | 보관 내용 |
| --- | --- |
| 급여V26_직원 | 직원별 급여·보험 설정과 수정번호 |
| 급여V26_월별 | 직원·귀속월별 현재 급여 기록과 확정 당시의 전체 계산 내용 |
| 급여V26_설정 | 사업장 정보, 연도별 공식 기준 확인 기록 |
| 급여V26_이력 | 변경 직전 자료, 작업·수정번호, 명세서 열람 기록 |

급여 정보가 들어간 스프레드시트 자체의 공유 권한도 원장이 관리해야 합니다. 웹 화면의 권한 검사는 스프레드시트에 직접 부여된 공유 권한을 제한하지 않습니다.

## 브라우저 호출 계약

공개 함수는 `payrollCommand(token, action, payload)` 하나입니다. 모든 작업은 먼저 기존 서버의 세션 검증을 통과하고 `role === 'owner'`여야 합니다. 화면에서 메뉴를 숨기는 것만으로 접근을 제한하지 않습니다.

| action | 주요 payload | 반환 내용 |
| --- | --- | --- |
| bootstrap | month (`YYYY-MM`) | 설정 여부, 직원, 선택 월 급여, 연간 합계, 해당 월 요율·상하한·근거 |
| saveEmployee | 직원 필드, id, revision | 저장한 employee |
| saveSettings | 사업장 필드, revision | 저장한 settings |
| approveYear | year, confirmed: true | 해당 자료 버전을 확인한 settings |
| preview | month, employeeId, payDate, inputs | calculation |
| saveDraft | preview 항목과 revision | calculation, run |
| finalize | month, employeeId, revision | 확정한 run |
| markPaid | month, employeeId, revision, paidDate | 지급 완료로 기록한 run |
| void | month, employeeId, revision, reason | 취소 기록 run |
| getPayslip | month, employeeId | 확정 당시 snapshot, status, revision |
| annualReport | year | rows, totals |

새 직원과 새 급여의 `revision`은 0입니다. 기존 자료를 수정할 때는 마지막으로 받은 수정번호를 다시 보냅니다. 다른 창에서 먼저 변경한 자료를 덮어쓰지 않습니다. 직원 이메일은 중복 등록할 수 없습니다.

급여 상태는 `draft → confirmed → paid`입니다. `confirmed`와 `paid`는 금액 수정이 금지됩니다. 정정 시 사유를 남겨 `void`로 전환하고 같은 직원·귀속월에 더 높은 수정번호의 초안을 저장합니다. 원래 확정 자료는 취소 기록과 변경 이력에 보관합니다. `markPaid`는 실제 송금 여부를 기록하는 기능이며 금융 거래를 실행하지 않습니다.

## 금액과 계산 규칙

- 금액은 원 단위 정수로 입력합니다. 시간·일수·배율은 소수 둘째 자리까지 입력할 수 있습니다. 빈 금액과 0원을 구분합니다.
- 기본급은 월급제의 기본 월급, 시급 × 유급 시간, 일급 × 유급 일수로 계산합니다. 자동 계산하는 시급제·일급제 기본급에 원 미만 금액이 생기면 올림하여 최저임금 경계에서 계산값이 부족해지지 않도록 합니다. 직접 입력한 기본급은 입력액을 유지하고 계산 방법과 최저임금 기준을 별도로 확인합니다.
- 지급·공제 항목은 각각 최대 30개입니다. 시간·단가·배율이 있으면 세 값을 모두 입력해야 하며, 곱한 금액의 원 미만을 버린 값과 지급액이 일치해야 합니다. 배율 자체의 법적 적용 여부는 근로형태·사업장 규모에 따라 확인합니다.
- 식대와 자가운전 보조금의 비과세 금액은 각각 월 20만 원의 합산 한도를 적용합니다. 항목을 나누어 넣어도 한도가 늘어나지 않습니다. 비과세 요건과 기타 비과세 근거는 항목 설명과 확인란에 기록합니다.
- 국민연금은 신고 기준소득월액의 1천 원 미만을 버리고 적용 기간의 상하한을 반영한 뒤 근로자 보험료를 계산합니다. 건강보험은 근로자 부담 보험료 상하한을 적용합니다. 각 근로자 보험료는 10원 미만을 버린 예상액입니다. 공단 고지액을 입력하면 고지액이 우선 적용되며 확인 근거가 필요합니다.
- 건강보험 고지액을 직접 입력하면 장기요양보험 고지액도 함께 입력합니다. 공단 정산·감면·자격 취득·상실에 따른 차이는 고지액과 근거로 반영합니다.
- 소득세는 해당 지급일의 간이세액표나 확인된 급여대행 자료의 금액을 직접 입력합니다. 가족·자녀 수와 80·100·120% 선택은 확인 근거로 저장하며, 입력 세액에 비율을 다시 곱하지 않습니다. 빈 세액은 0원으로 확정되지 않습니다.
- 산재보험과 사업주 고용안정·직업능력개발 부담금은 직원 급여에서 공제하지 않습니다. 사업주 전체 인건비 정산은 이 모듈의 범위에 포함하지 않습니다.
- 최저임금 비교에는 기본급 또는 별도로 입력한 산입 대상 금액과 해당 유급 시간을 사용합니다. 월급제는 기간 유급 시간이 입력되면 그 시간을, 아니면 직원 설정의 월 유급 시간을 사용합니다. 시급제·일급제는 해당 급여 기간의 전체 유급 시간을 사용합니다. 산입 기준과 시간은 최종 확인이 필요합니다.

## 연도·시행월 관리

요율은 공개 홈페이지에서 임의로 가져오는 방식이 아니라, 공식 근거와 함께 배포한 자료 버전으로 관리합니다. 현재 등록된 연도는 2025·2026·2027년입니다. 원장이 해당 연도의 근거를 확인해야 급여를 확정할 수 있습니다. 자료 버전이 변경되면 다시 확인합니다.

2027년 건강보험·장기요양보험은 2026-11-20까지 확인한 정부 발표 기준입니다. 2027년 건강보험 상하한은 확인되지 않았으므로 건강보험·장기요양보험 **공단 고지액이 있어야 확정**할 수 있습니다. 국민연금 상하한은 2027년 6월까지 확인되었고, 2027년 7월 이후에는 국민연금 고지액이 필요합니다. 등록되지 않은 연도는 이전 연도 요율로 대체하지 않고 확정을 막습니다.

장기요양보험 계산은 2025년과 2026년 1~10월에는 소득 대비 요율/건강보험 요율의 정확한 비율을 사용합니다. 개정법 적용례에 따라 2026년 11월부터 반올림한 비율을 적용합니다. 단순히 모든 달에 표시용 12.95%·13.14%를 곱하지 않습니다. 공식 근거는 화면의 정부 기준 요율 탭과 `BWP26_SOURCES_`에 있습니다.

확정 자료에는 당시의 직원·사업장 정보, 계산 입력, 요율, 상하한, 설명을 모두 복사해 보관합니다. 나중에 직원 급여나 요율 자료를 바꿔도 이미 확정한 명세서는 바뀌지 않습니다.

## 저장·조회 안정성

모든 요청은 원장 권한 확인 후 스크립트 잠금을 얻습니다. 수정할 행을 찾고 수정번호를 비교하는 작업도 잠금 안에서 실행합니다. 월별 자료의 키는 `귀속월|직원ID`이며 중복 키가 있으면 처리를 중단합니다.

조회 시 전체 키 인덱스를 읽어 오래된 자료도 찾되, 급여 JSON은 필요한 귀속연도·직원 기록만 읽습니다. 최근 몇백 행만 읽고 그 이전 자료를 없는 것으로 처리하지 않습니다. 시트당 20,000개 기록을 초과하면 명확한 보관·분할 안내와 함께 중단합니다.

변경 이력의 `phase: intent`는 변경 직전 기록입니다. 이력을 먼저 저장하고 하나의 기준 행을 갱신합니다. 시트 쓰기가 실패하면 이력에는 시도 기록이 남을 수 있으므로 현재 기준 행의 수정번호로 완료 여부를 확인합니다. 임의 자동 재시도는 하지 않습니다. 원장 화면을 새로고침하면 실제 저장 상태를 확인할 수 있습니다.

## 검증 범위

`node tests/payroll.test.cjs`는 가상 Sheets·인증 객체에서 권한, 유효성 검사, 계산 경계, 수정 충돌, 확정 자료 보존, 취소 이력, 조회 범위와 잠금을 검증합니다. 실제 Apps Script 권한 승인, 운영 스프레드시트, Google 웹앱 배포는 별도 환경이므로 이 테스트 통과를 실제 Google 서비스 통합 검증으로 표현하지 않습니다.

급여명세서는 확정된 snapshot으로 브라우저에서 인쇄하거나 PDF로 저장합니다. 서버가 외부 공유 링크를 만들거나 직원에게 메일을 보내지 않습니다. 원본 엑셀의 VBA와 사용자 정의 계산 함수를 실행·이식한 것은 아니며, 예스폼 프로그램과의 전체 동작 동일성을 보장하는 표현을 사용하지 않습니다.
