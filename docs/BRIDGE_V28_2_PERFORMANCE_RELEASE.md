# Bridge Wonder V28.2 — 기존 V27.1과 충돌 없이 추가한 성능 개선

## 현재 구조
- GitHub `/staff/`: 로그인 화면과 기본 대시보드, 수업반 편집 양식, 메뉴 텍스트를 직접 렌더링합니다.
- Google Apps Script: `StaffBridge.gs`의 승인된 HTTP POST 요청을 받아 기존 로그인·직원 권한·급여 및 학생 정보 서버 함수를 실행합니다.
- Google Sheets/Drive: 실제 수강반·아이·보호자·출결·급여·PDF 등 개인정보와 운영 원장만 저장합니다.
- Cloudflare·외부 중계 서버·별도 데이터베이스를 추가하지 않았습니다. HTTP POST 자체는 Google API 통신입니다.

## V28.2 변경사항
- V27.1에 이미 반영되어 있던 'GitHub 정적 UI + 익명 health 1회' 및 기본값 설정을 보존했습니다.
- 오늘의 업무 메뉴는 서버 요약이 도착하기 전에 표시되며, **기본 집계**와 **확인할 업무**를 서로 기다리지 않고 병렬로 요청합니다.
- 홈을 새로고침하거나 다른 메뉴로 이동했을 때 늦은 조회 결과가 이전 화면으로 나타나지 않도록 홈 렌더 시퀀스 검사를 강화했습니다.
- 모바일 업무 선택 메뉴의 옵션을 화면 이동마다 다시 만들지 않도록 경량화했습니다.
- 로그인 서버 상태를 고정 화면 오버레이 대신 로그인 카드 안에 배치했습니다.
- 수동 서버 재검사 시 검증 완료 플래그를 먼저 해제하므로, 재검사가 실패했는데도 이전 성공 상태를 그대로 신뢰하는 문제를 막았습니다.

## 적용 및 점검
1. V28.2는 GitHub 코드만 변경하며 Google Apps Script 파일과 기존 Sheets는 교체하지 않습니다.
2. `/staff/`에 접속하면 정적 로그인 화면이 먼저 표시됩니다. Google 연결 검사에 성공한 후 비밀번호/업무 정보를 전송합니다.
3. 원장으로 로그인 후 **오늘의 업무**가 먼저 나타나고 집계 수치가 나중에 바뀌는지 확인합니다.
4. **수업 시간표·상담 접수·출석 체크·직원 급여관리**를 각 메뉴에서 열어 조회합니다.
5. 선생님 테스트 계정으로는 원장 전용 급여관리 메뉴가 보이지 않아야 하고, 실제 서버 RPC도 차단되어야 합니다.
6. 실제 급여 확정·송금 기록은 테스트 데이터로만 시도하고, 운영 금액을 임의로 입력하지 않습니다.

## 검증 범위
- 새 V28.2 정적/비동기 검사 + 기존 V27.1 직원·가속·급여·권한 테스트를 GitHub CI에서 실행.
- 별도의 V28 시뮬레이션(2초 지연 서버, PC/모바일)은 정적 선출력 방식의 가능성을 확인했지만 실제 배포 환경의 지연 시간을 보증하지 않습니다.
- 실제 Google 계정·Google Sheets·Drive·PDF 인쇄 및 계정 간 권한은 사용자 환경에서 확인해야 합니다.

## 복구
Google Apps Script를 수정하지 않았으므로 문제 발생 시 V28.2의 GitHub 병합 커밋만 revert하면 됩니다. 실제 업무 데이터는 그대로 유지합니다.
