# Bridge Wonder V28 — GitHub 즉시 표시 · Google 데이터 필요시 조회

## 적용 목표
신전캐나다 관리자 사이트처럼 GitHub Pages의 `/staff/`에서 로그인과 기본 메뉴·양식을 즉시 표시합니다. iframe 또는 Google 페이지로 자동 이동하지 않습니다. 데이터가 필요한 화면에서만 기존 Google Apps Script 웹앱의 `doPost`를 HTTPS POST로 호출합니다. 추가 Cloudflare, 서버, 별도 DB 없음.

**HTTP POST는 엄밀히 Google Apps Script API 통신입니다.** 외부 API 제공업체는 사용하지 않습니다.

## 이번에 변경한 파일
- `staff/index.html`: 실제 운영용 GitHub 독립 로그인·전체 업무 UI. 기존 시각 테마와 로고 유지.
- `staff/standalone.html`: 이전 검증 링크를 위한 동일 화면 유지.
- `assets/js/staff-static-defaults.js`: 비민감 기본값(과정 코드·이름, 메뉴 역할명, 요일 라벨). 실제 교습비·시간·학생 데이터는 포함하지 않음.
- `assets/js/staff-google-bridge.js`: 익명 `bridgeHealth` 1회 자동 검증, 중복 검증 결합, 성공 후에만 로그인/데이터 요청 전송.
- `assets/js/administration.js`: 메뉴와 빈 집계칸을 먼저 표시하고 현재 대시보드 수치를 비동기 조회. 업무알림 비동기 로딩. 모바일 메뉴 반복 생성 제거.
- `tests/`와 GitHub Actions: 로그인 게이트웨이, 권한, 급여, 가속, 정적 UI 회귀검사.

## 데이터의 위치
| 정보 | GitHub 정적 파일 | Google 서버 |
| --- | --- | --- |
| 디자인, 메뉴 명칭, 일반 과정 이름, 요일 표현 | 저장 | 필요 없음 |
| 실제 개설 수업반, 시작일, 시간, 교습비, 환불 기준 | 저장하지 않음 | 조회·수정 |
| 아동·보호자·전화번호·상담·출결 | 저장하지 않음 | 권한 확인 후 조회·수정 |
| 원장·선생님 권한, 이메일 비밀번호 검증, 세션 | 비밀키 없음 | 검증·관리 |
| 직원 급여·세금·PDF·수납 | 저장하지 않음 | 원장 권한 확인 후 처리 |

브라우저에는 기존 세션 토큰만 `sessionStorage`에 유지되며 서버에서 다시 검증합니다. **서버 데이터는 영구 웹 저장소에 넣지 않습니다.** 짧은 메모리 캐시는 운영 요약·수업반 정보 일부에만 적용합니다.

## 초기 로딩
1. GitHub 정적 HTML과 CSS/JS가 로그인 화면을 즉시 표시합니다.
2. 익명 `bridgeHealth` 요청을 한 번 보냅니다. Google 계정 선택/iframe이 필요 없습니다.
3. 연결이 검증되면 기존 등록 이메일+비밀번호 또는 최초 인증 흐름이 작동합니다.
4. 로그인한 계정이 원장이면 원장용 메뉴, 교사면 부여된 메뉴만 보입니다. 서버도 각 업무 RPC마다 권한을 확인합니다.
5. 홈은 정적 바로가기를 즉시 표시하며 운영 집계와 확인할 업무는 응답 도착 후 화면에 채웁니다.
6. 급여·상담·출결·문서 등 업무 자료는 해당 메뉴를 열 때만 요청합니다. 급여 모듈 JS/CSS도 원장이 메뉴를 열 때만 로드합니다.

## Google Apps Script 적용
이 버전에서는 기존 `Code.gs`, `Payroll.gs`, `Admin.html`, `StaffBridge.gs`를 변경하지 않았습니다. 이전 V27에서 **`StaffBridge.gs`와 웹앱 새 배포**를 끝내셨고 연결 검사에 성공했다면, Google 프로젝트를 다시 수정할 필요가 없습니다. 새 테스트 서버를 만들지 마세요.

- Google Health 검사 실패 → 로그인 요청은 전송되지 않습니다. `연결 상태 다시 확인` 버튼으로 재시도.
- 이미 기존 Google 화면을 사용하시려면 로그인 화면의 `Google 화면으로 직접 접속` 링크 사용.
- 저장 요청은 장애 시 자동 재시도하지 않습니다. 원본 데이터를 먼저 확인한 뒤 다시 실행해야 합니다.
- Google의 CORS/ContentService 리디렉션·서버 제한과 로그인 PBKDF2 처리시간은 별도의 실제 운영 테스트 대상입니다.

## 테스트 및 롤백
- Chromium PC 1440×900/모바일 390×844 모의 서버 테스트: Google 대시보드 응답 2초 지연, 정적 메뉴 즉시 표시·실제 수치 후속 갱신·가로 넘침/JS 오류 확인.
- GitHub Actions: 기존 급여·보안·직원 화면·가속 테스트와 새 연결·정적 UI 테스트 각각 성공.
- 실제 Google 원장/선생님 권한별 로그인, 문서 발급, 실제 급여 저장 및 PDF 결과는 이 자동 테스트에 포함하지 않음.
- 되돌릴 때 GitHub `main`의 V28 병합 커밋을 `git revert`로 되돌립니다. Sheets는 유지합니다.

**주의:** 직원이 많이 늘더라도 HTTP 요청의 무제한 호출은 보장되지 않습니다. Apps Script 실행·동시 처리 및 Sheets/Drive 할당량을 지켜야 합니다.
