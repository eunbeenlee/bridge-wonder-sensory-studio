## 정적 검증

`npm run check`는 다음을 네트워크 없이 검사하며 오류 0건으로 통과했습니다.

- JavaScript·Apps Script·인라인 스크립트 문법 20개
- JSON·구조화 데이터 6개
- HTML 14개 파일의 중복 ID·속성·클래스 및 라벨 참조
- 로컬 링크·리소스·앵커 229개
- 원본 HTML에서 다시 생성한 직원 레이아웃과 배포 파일 일치
- 기존 CSS·이미지 12개가 기준 커밋과 바이트 단위로 일치

기준 커밋: `f995dff0fad304703ac6e413b0a3c9319d29cfe7`. 급여 전용 CSS와 기존 인라인 로고를 그대로 분리한 파일은 허용된 추가입니다. 레이아웃 재생성은 임시 디렉터리에서 실행하므로 검사 과정이 저장소를 변경하지 않습니다.

GitHub Actions의 `Verify Bridge Wonder` 작업이 PR과 main 갱신 때 같은 검사를 실행합니다. 액션은 공식 저장소에서 확인한 커밋으로 고정하며, 저장소 읽기 권한만 사용합니다.

## 확인하지 않은 운영 범위

이 기록의 자동 검증은 실제 Google 배포, 운영 계정 로그인, Gmail 전송, Drive 공유 상태, 운영 Sheets에 대한 쓰기를 실행한 결과가 아닙니다. jsdom은 DOM 동작을 검사하며 실제 화면 배치·기기별 표시·종이 인쇄 결과를 그리는 브라우저가 아닙니다. 급여 PDF 파일의 최종 인쇄 모습은 Google 웹앱 적용 후 확인해야 합니다.

원본 XLSM의 VBA는 실행하지 않았습니다. 코드에 등록한 공식 기준의 계산 검증과 예스폼 프로그램 전체의 동등성 검증은 서로 다릅니다.

GitHub와 공개 웹사이트의 실제 반영 결과는 병합 PR·커밋·GitHub Actions 배포 이력으로 확인합니다. Google 적용은 `BRIDGE_V26_RELEASE.md`의 별도 절차를 따릅니다.
