# Bridge Wonder V26 최종본 적용 안내

작성일: **2026-11-20, 한국 시간**

## 1. 이번 버전에 포함된 내용

공개 웹사이트 문장을 다듬고 기존 테마를 유지했습니다. 원래의 CSS·이미지 파일 12개는 V25.1 기준 커밋과 바이트 단위로 같습니다. 직원 로그인 화면의 기존 로고는 같은 이미지 데이터를 별도 파일로 옮겼으며, 급여 전용 스타일만 추가했습니다. 연령·연락처·주소·수업 조건 같은 운영 사실은 임의로 바꾸지 않았습니다.

직원 운영공간은 중복 요약 조회를 합치고, 동시에 실행하는 실제 읽기 요청을 4개로 제한합니다. 요약 수치는 짧게 재사용하지만 개인정보·급여 응답은 캐시에 저장하지 않습니다. 화면 이동·로그아웃 이후 도착한 응답과 저장 전 시작한 오래된 조회가 현재 화면을 덮어쓰지 않도록 처리했습니다. 가속 엔진을 불러오지 못해도 기본 Google 호출로 화면을 시작합니다.

급여 기능은 원장 계정에서만 사용할 수 있습니다. 서버가 모든 요청의 원장 권한을 검증하며 직원에게 다른 사람의 급여를 보여주는 기능은 없습니다.

| 메뉴 | 주요 기능 |
| --- | --- |
| 월별 급여 | 직원·귀속월 선택, 지급·공제, 계산 미리보기, 초안 저장, 확정, 지급 완료 기록, 취소 사유, 명세서 인쇄 |
| 직원 급여설정 | 월급·시급·일급, 입퇴사일, 부서·직위, 보험 가입 구분 |
| 정부 기준 요율 | 연도·시행월별 보험료와 최저임금, 공식 출처, 원장 확인 기록 |
| 연간 지급현황 | 귀속연도별 내역, 상태별 구분, CSV 내려받기 |
| 사업장 정보 | 명세서에 사용할 실제 상호·사업자번호·대표자·주소 |

과거 확정 내용은 직원 설정이나 요율이 바뀌어도 보존됩니다. 다른 창에서 먼저 저장한 내용을 오래된 수정번호로 덮어쓰지 않습니다. 실제 지급일은 확정 당시의 지급 예정일과 구분해 명세서·월별 대장·연간 CSV에 표시합니다.

## 2. GitHub와 Google에 적용할 파일

GitHub의 최종본이 반영되어도 Google Apps Script의 코드가 자동으로 바뀌지는 않습니다. 원장 급여 기능을 실제로 사용하려면 아래 **직원용 Google 웹앱 갱신**을 완료해야 합니다.

| 대상 | 적용 파일 | 역할 |
| --- | --- | --- |
| GitHub Pages | 저장소의 공개 HTML·assets·staff | 홈페이지·직원 화면·가속·급여 화면 |
| 직원 Apps Script | `server/apps-script/Code.gs` | 기존 직원 업무 전체 및 보안·권한·수납 보완 |
| 같은 직원 Apps Script | `server/apps-script/Payroll.gs` | 원장 급여 계산·저장·확정·이력 |
| 같은 직원 Apps Script | `server/apps-script/Admin.html` | V26 GitHub 화면을 불러오는 Google HTML 진입점 |

기존 파일을 지우고 새 Google 프로젝트를 만들 필요는 없습니다. 현재 사용 중인 직원 프로젝트와 기존 `/exec` 배포 주소를 유지합니다. `Payroll.gs`의 함수들을 `Code.gs`에 중복으로 붙여 넣지 않습니다.

### Google 웹앱 갱신 순서

1. 원장 Google 계정으로 **기존 직원 운영공간 Apps Script 프로젝트**를 엽니다. 현재 코드와 스프레드시트를 복사해 복구본으로 보관합니다.
2. 기존 `Code.gs`를 제공한 전체 파일 내용으로 교체하고 `Payroll.gs`를 새 스크립트 파일로 추가합니다. `Admin.html`도 제공한 파일로 교체합니다.
3. 프로젝트 설정의 Script Properties에서 기존 `SPREADSHEET_ID`, `OWNER_EMAIL`이 맞는지 확인합니다. 기존 인증 비밀키·암호 관련 속성은 삭제하거나 공개 코드에 옮기지 않습니다.
4. 편집기에서 `setupStaffDocumentsV19`를 한 번 실행합니다. 기존 문서·백업 폴더를 재사용하고 예전 백업 트리거만 비공개 함수 이름으로 옮깁니다. 다른 트리거는 유지합니다.
5. 편집기에서 `setupBridgeWonderPayrollV26_`를 실행합니다. 활성 Google 계정이 `OWNER_EMAIL`과 일치해야 합니다. 급여용 시트 4개만 추가하며 기존 계정·수강생 자료를 덮어쓰지 않습니다.
6. **배포 → 배포 관리 → 기존 웹앱 수정 → 새 버전 → 배포**로 갱신합니다. 기존과 동일한 실행 계정·접근 설정 및 배포 주소를 유지합니다. 서버의 자체 로그인·권한 검증을 거친 요청만 개인정보에 접근합니다.
7. 직원 운영공간을 새로고침하고 다시 로그인합니다. 원장 메뉴의 **직원 급여관리**에서 사업장 정보 → 직원 급여설정 → 정부 기준 요율 확인 → 월별 급여 순서로 입력합니다.

이전 형식으로 이미 발급된 일회용 인증번호는 새로 요청해야 합니다. 기존 로그인 세션을 일괄 삭제하지는 않습니다. 급여 정보가 보관되는 스프레드시트의 직접 공유 대상도 원장 계정에서 확인합니다.

급여 메뉴가 보이지 않는다면 원장 계정 여부, Google 웹앱 새 버전 반영 여부, 서버 권한 설정을 차례로 확인합니다. 화면만 바꾸고 이전 Google 서버를 계속 사용하면 신규 급여 API가 없습니다.

## 3. 급여 계산 운영 기준

현재 등록된 연도는 2025·2026·2027년입니다. 정부 공식 자료의 발표일·시행 구간을 확인한 값을 배포본에 넣었으며, 새로운 고시를 인터넷에서 읽어 무검토로 적용하는 자동 갱신 기능은 아닙니다. 등록되지 않은 연도에는 확정을 차단합니다.

| 항목 | 2025 | 2026 | 2027 |
| --- | ---: | ---: | ---: |
| 국민연금 근로자 부담률 | 4.5% | 4.75% | 5.0% |
| 건강보험 근로자 부담률 | 3.545% | 3.595% | 3.595% |
| 장기요양 표시 비율, 건강보험 대비 | 12.95% | 13.14% | 13.90% |
| 고용보험 근로자 부담률 | 0.9% | 0.9% | 0.9% |
| 최저시급 | 10,030원 | 10,320원 | 10,700원 |

국민연금 상하한은 매년 7월의 적용 기간으로 구분합니다. 2026년 11월 장기요양보험의 비율 반올림 방식 변경도 별도로 적용합니다. 표시용 비율을 과거 모든 달에 일괄 곱하지 않습니다.

2027년 보험 요율은 확인된 정부 발표 기준이며 시행 예정으로 표시합니다. **2027년 건강보험 상하한과 2027년 7월 이후 국민연금 상하한은 이번 자료에서 확정하지 못했습니다.** 그 기간에는 해당 공단 고지금액을 직접 입력해야 확정할 수 있습니다. 확인되지 않은 상하한을 전년도 값으로 대신 넣지 않습니다.

소득세·지방소득세는 실제 지급 시점에 유효한 법정 간이세액표 등으로 확인한 금액을 입력합니다. 급여 화면에 2026년 3월 적용 법정 표와 국세청 일반 안내를 구분해 연결했습니다. 가족·자녀 수와 선택 비율, 확인 근거를 함께 저장합니다. 원본 2025년 엑셀의 표나 오래된 안내 예시를 다른 연도에 자동 적용하지 않습니다.

미입력 보험료·세액은 0원으로 취급하지 않습니다. 미리보기·초안에는 **확인 필요**로 표시하고 확정을 막습니다. 시급·일급에 소수 시간·일수를 곱해 기본급을 자동 산정할 때는 원 미만을 올림합니다. 직접 입력한 기본급은 변경하지 않으며 최저임금 검사를 수행합니다. 사업장별 수당 배율·비과세 요건·산입 범위·중도 입퇴사 계산 근거는 원장이 확인해야 합니다.

급여 확정 후 실제 지급일이 달라져 적용 세액이나 법정 기준에 영향이 생기면, 지급 완료만 기록하기 전에 기존 확정을 사유와 함께 취소하고 새 기준으로 검토·확정합니다.

명세서는 확정 내용을 별도 창에서 인쇄하거나 브라우저 기능으로 PDF 저장합니다. 지급 완료 버튼은 송금 사실을 기록하는 기능입니다. 실제 은행 이체·이메일 발송·공단 신고·세무 신고는 실행하지 않습니다.

## 4. 엑셀 대응 범위

제공된 XLSM은 원본을 변경하지 않고 19개 시트, 42개 이름 정의, 474개 수식 셀, 유효성 검사와 숨김 시트 구조를 분석했습니다. 자세한 시트별 대응은 `BRIDGE_V26_EXCEL_MAPPING.md`에 있습니다. 원본의 실제 이름·계좌·회사 정보·급여 자료는 GitHub 또는 배포본으로 옮기지 않았습니다.

직원 설정, 급여대장, 명세서, 연간 내역이라는 업무 흐름을 웹에 독립 구현했습니다. 원본 VBA의 사용자 정의 함수 전체, 간이세액표 자동 조회, 퇴직금·연말정산, 사업주 전체 보험 부담, 근태 자동 연동까지 원본과 동일하게 복제한 것은 아닙니다.

## 5. 공개 전 운영자가 확정할 정보

기존 개인정보 안내에는 아직 실제 법정 상호, 등록 정보, 개인정보 책임자, 항목별 보유기간 및 Google 처리 관련 세부 안내가 확정되지 않은 부분이 있습니다. 이번 문안 수정에서는 그 내용을 임의로 만들어 넣지 않았습니다. 원장의 **학원 운영정보**에 실제 등록증·교습비·환불 기준을 입력하고 공개 개인정보 안내와 일치시킵니다.

검증 결과와 실제 Google 실행을 하지 않은 범위는 `BRIDGE_V26_QA.md`를 확인합니다. V25·V25.1 문서는 이전 구조의 기록이며 이번 적용은 V26 안내를 우선합니다.

## 6. 복구 방법

GitHub 문제는 V26 병합 커밋을 되돌리는 새 커밋으로 복구합니다. 이력을 강제로 덮어쓰지 않습니다. Google 웹앱은 배포 관리에서 보관한 이전 버전을 다시 선택할 수 있습니다.

기존 Google 코드로 되돌리더라도 새 급여 시트나 수납의 추가 작업 ID 열을 임의 삭제하지 않습니다. 확정 급여·취소 이력과 실제 수납은 보존하고 원장 확인 후 처리합니다. 화면에서 결과가 불명확한 저장을 자동 반복하지 않으며, 먼저 실제 기록을 조회합니다.
